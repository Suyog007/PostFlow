# Atomize articles, render cards, skip bots

No existing project does what PostFlow does end-to-end: a GitHub survey found **no dedicated AI-news→X/LinkedIn poster above 1,000 stars**, while the closest open-source analog (a 13-star RSS-to-LinkedIn bot) and the 37.2k-star Postiz between them already demonstrate every mechanic PostFlow needs to borrow ([martinopedal/linkedin-auto-poster](https://github.com/martinopedal/linkedin-auto-poster), [Postiz](https://github.com/gitroomhq/postiz-app)). The concrete answer to "what next" is three builds that copy proven patterns rather than invent new ones: a **paste-a-URL / own-writing intake that extracts and atomizes articles into typed fragments before drafting** (the repurposing pattern with the strongest open-source precedent, and the only input with zero copyright friction); a **deterministic card renderer (satori + sharp) with native image upload to both platforms** — necessary because **Fireworks deprecated image generation on June 10, 2026** with no migration path, and preferable because platform-trust evidence favors clean stat/quote cards over AI art; and an **engagement-preset pack** shipping the formats the evidence actually supports — LinkedIn document carousels are the only format ranked #1 in two independent 2026 studies, while on X text with a genuine question ending beats everything, and link posts are simultaneously the weakest format and, on X, 13× more expensive to publish ($0.20 vs $0.015). Two things must not change: publishing stays API-only and human-approved — X's developer policy requires showing exactly what will be published, which makes PostFlow's revision-bound approval gate a compliance mechanism, not just UX — and no automated engagement actions (likes, replies, DMs, follows) should ever be built. The largest unresolved risk is legal rather than technical: LinkedIn's API Terms §3.1(26) bans using the APIs to "automate posting" even as LinkedIn's own Share product does exactly that for member-authorized apps.

## The market assembled every part of this desk except the desk itself

The closest thing to PostFlow in the wild is a 13-star Python repo. **martinopedal/linkedin-auto-poster** runs a 06:00 UTC GitHub Actions cron that fetches RSS feeds and GitHub Releases, scores items with a deterministic additive formula (exclude-keyword hard drops; category hits double-counted; GA=3 / public preview=2 / retirement=2 / private preview=1 weights; standalone threshold 12, with below-threshold items routed to a weekly roundup), researches claims with tool-using agents, drafts with Claude Opus, critiques with GPT-5.4, validates against 50-plus banned AI-sounding phrases plus URL allowlists, and publishes only after a human adds an `approve-post` label to a generated pull request ([repo](https://github.com/martinopedal/linkedin-auto-poster)). Nobody has replicated that scope at scale, which is evidence that PostFlow's position — a news-quality layer plus an approval machine — is real rather than crowded.

The systems with scale treat news as a plug-in. **Postiz (37,225★, AGPL-3.0)** is the reference implementation for the publishing half: RSS auto-posting with optional AI rewriting, a "Generate picture" toggle, next-available-slot spreading so feed bursts don't dump five posts at once, threads with per-part delays, shareable approval previews, "Plugs" that auto-repost and auto-comment when a post performs well, and reconcile endpoints for when a platform returns a missing post ID ([repo](https://github.com/gitroomhq/postiz-app), [RSS docs](https://docs.postiz.com/general/automations/auto-post-rss), [docs index](https://docs.postiz.com/)). **BrightBean Studio (2,472★)** and **TryPost (707★)** converge on the same 2026 architecture — direct first-party APIs, automatic retries, per-account rate-limit tracking, configurable approval stages, 90-day publish audit logs, and agent-drivable interfaces ([BrightBean](https://github.com/brightbeanxyz/brightbean-studio), [TryPost](https://github.com/trypostit/trypost)) — while **Mixpost (3,817★)** ships per-network post versions plus automated follow-up comments on high-performing posts ([repo](https://github.com/inovector/mixpost)). Demand is visible in the no-code world too: n8n hosts **542 LinkedIn templates, 372 news templates, and 177 Twitter templates**, with the most-viewed LinkedIn workflow (27.9k views) being a Google-Sheets queue plus LLM plus email approval, and the second (20.6k views) adding DALL-E image generation ([n8n #4005](https://n8n.io/workflows/4005/), [n8n #4968](https://n8n.io/workflows/4968/)). Zapier's Twitter integration was deprecated in August 2023 over X API pricing ([Zapier](https://zapier.com/apps/rss/integrations/twitter)) — history that validates PostFlow's own-credentials, self-hosted design.

Where the ecosystem is weak is where PostFlow is already strong. Ranking quality in the wild has two designs: hand-tuned additive keyword weights (martinopedal — conceptually what PostFlow does pre-LLM) and learned preference profiles: **condenseit (89★)** blends keywords, TF-IDF, embeddings and an optional LLM rerank, shows a "Why ranked here?" breakdown per item, and learns from explicit 1–5 star ratings plus implicit signals (read ≈ 3.8 stars, save-for-later ≈ 4.5, dismiss ≈ 1.5) with a 30-day half-life time decay that activates after five ratings ([repo](https://github.com/wildlifechorus/condenseit)). Reconciliation after ambiguous publishes is shipped by almost nobody except Postiz; approval enforcement stronger than an email or Slack confirmation exists almost nowhere; and **Wifsimster/solopilot's** operating charter — "never acts on your behalf without validation," a $200/month budget with an 80% alarm and hard stop, and an ADR showing hourly collection plus daily publishing costs the same AI spend as one daily run while covering 24× more ([repo](https://github.com/Wifsimster/solopilot)) — reads like a restatement of PostFlow's own design goals. The survey's clearest negative finding: the popular browser-automation cluster (**jihe520/social-push**, 533★, drafts-only but drives the user's logged-in browser; solopilot scrapes X with session cookies) is explicitly prohibited by both platforms and should not be copied at any phase ([social-push](https://github.com/jihe520/social-push)).

## Platform mechanics now pay for conversation; the evidence points at artifacts

The strongest replicated finding across two independent 2026 datasets is that **LinkedIn document/carousel posts are the top engagement format**. Socialinsider's analysis of 1.3M posts put native documents at **7.00% engagement rate** (+14% YoY), ahead of multi-image (6.45%), video (6.00%), image (5.30%), text (4.50%), poll (4.20%) and link (3.25%) ([Socialinsider](https://www.socialinsider.io/social-media-benchmarks/linkedin)); Buffer's 45M-post study put LinkedIn carousels at a **median 21.77%** — 196% above video and 585% above text-only — with the same rank order ([Buffer](https://buffer.com/resources/data-best-content-format-social-media/)). The absolute numbers differ between studies (don't compare them across sources); the ranking is consistent, and practitioner commentary explains carousels as "free value" — downloadable frameworks and checklists ([Socialinsider](https://www.socialinsider.io/social-media-benchmarks/linkedin)). On X the ranking inverts toward text: **text leads median engagement (3.56%)**, marginally above images (3.40%) and video (2.96%), with **links last (2.25%)** ([Buffer](https://buffer.com/resources/data-best-content-format-social-media/)). Video wins reach while carousels and text win depth, and LinkedIn cadence data (2M+ posts) favors **2–5 posts per week**, with LinkedIn's team describing no format as algorithmically privileged ([Buffer](https://buffer.com/resources/linkedin-algorithm/)). The format the owner asked about directly — "what if we used X to make trading decisions"-style thought experiments, contrarian takes, myth-busting — has **no quantitative support in any study found**: treat these as rhetorical wrappers around evidence-backed structures (news plus original commentary, frameworks, data drops, real experiments), to be validated on-account, not as proven formats to scale.

X is now the most transparent major platform because its ranking code is public. For You candidates are scored by a single transformer ("Phoenix") predicting the viewer's probability of dozens of actions — likes, replies, reposts, quotes, shares, clicks, dwell-type attention metrics, follows, plus negatives like report, mute, block and "not dwelled" — combined as a weighted sum ([xai-org/x-algorithm](https://github.com/xai-org/x-algorithm)). The visible base weights reveal the intent: **ReplyWeight 5.0 against FavoriteWeight 0.5** — a predicted reply is worth 10× a predicted like — and a July 2026 "bidirectional follow" boost added **+15 to the reply weight for original posts from mutual follows** (shipped at 20 on July 13, lowered to 15 on July 24 after feedback) ([BIDIRECTIONAL_BOOST_CHANGE.md](https://github.com/xai-org/x-algorithm/blob/main/docs/BIDIRECTIONAL_BOOST_CHANGE.md)). Two constraints matter for scheduling design: **candidates older than 48 hours are filtered out of For You**, and repeated posts by one author are decayed by author-diversity multipliers — so late-bloom strategies don't exist and serial posting of near-identical content is self-defeating ([README](https://github.com/xai-org/x-algorithm)). Popular multipliers circulating in press ("reposts 20×, replies 13.5×, bookmarks 10×") **conflict with X's own August 2026 clarification that weights scale predicted probabilities, not raw counts**, and bookmarks aren't even among the ranked predicted actions ([Sprout](https://sproutsocial.com/insights/twitter-algorithm/), [README](https://github.com/xai-org/x-algorithm)). The code-consistent playbook: post originals designed for replies and dwell, cultivate mutuals, don't rely on late engagement, vary angle and format.

LinkedIn publishes no weights, and its team describes ranking as **relevance, expertise and meaningful engagement**, with reach expanding or contracting continuously rather than in a single early window ([Sprout](https://sproutsocial.com/insights/linkedin-algorithm/)). Enforcement is more explicit than ranking: emoji or reaction polls "meant to artificially boost engagement," chain-letter requests, and excessive repetitive comments are defined spam ([LinkedIn Help](https://www.linkedin.com/help/linkedin/answer/a1338787)); LinkedIn's 2026 posture reduces "low-value content that prioritizes engagement mechanics over original insight" ([Sprout](https://sproutsocial.com/insights/linkedin-algorithm/)); and pods — agreeing ahead of time to like or re-share each other's content — are banned outright ([Professional Community Policies](https://www.linkedin.com/legal/professional-community-policies)). One measurable operator lever is the comment loop: **replying to comments correlates with ~30% more engagement** across 72,000 analyzed posts — a notification-driven human action, since automated commenting is prohibited ([Buffer](https://buffer.com/resources/linkedin-algorithm/)). Best-time guidance conflicts between vendors (Buffer says 3–8 p.m. weekdays; Sprout says Tue–Thu business hours), which supports PostFlow's posting-windows-plus-suggestion model over any fixed optimum; hashtags are a nice-to-have capped at ~3; and links in the first comment appear not to hurt performance ([Buffer](https://buffer.com/resources/linkedin-algorithm/)). Polls remain a poor fit: they lead impressions only for pages above 50K followers and sit adjacent to LinkedIn's own spam examples ([Socialinsider](https://www.socialinsider.io/social-media-benchmarks/linkedin)).

An operational line that survives both platforms' texts: **sustainable engagement is content that would still exist if the metric didn't; farming is content engineered to harvest ranked interactions at the expense of informational value.** LinkedIn's spam categories and X's authenticity policy (which bans coordinating engagement exchange in "Likes, Polls, Replies, Reposts…" and metric inflation) draw the same line from the enforcement side ([X Authenticity Policy](https://help.x.com/en/rules-and-policies/authenticity)). The reputational cost is rising: **~25% of long-form posts on LinkedIn and X appear AI-generated** ([The Register](https://www.theregister.com/ai-and-ml/2026/07/09/ai-slop-writing-has-taken-over-the-internet-particularly-linkedin-and-x/5269525)), LinkedIn shipped a "report AI-generated slop" button ([TechCrunch](https://techcrunch.com/2026/07/30/linkedin-adds-a-button-to-report-ai-generated-slop/)), and a controlled Nature experiment found AI-assisted content raises engagement volume while lowering perceived quality and authenticity ("robotic," "generic," more dislikes), recommending transparent disclosure ([Nature Scientific Reports](https://www.nature.com/articles/s41598-026-40110-8)). For PostFlow the practical reading: the approval gate, first-person framing, and a deliberate no-bait policy are not friction — they are the product.

Encoding moves into three cheap layers, because PostFlow's angle-first prompts and one-click rewrite presets already exist. First, a **format pack** added to the rewrite menu: "Thread draft (X)" (8–12 parts), "Framework carousel script (LinkedIn)" (6–10 slides, each a stat, claim or takeaway), "Add a genuine question," "What-if thought experiment" (a wrapper: state the decision scenario, apply one sourced capability, land on the owner's conclusion), "Contrarian take on a sourced claim," "3 takeaways," and "Quote + take" for highlighted passages. Second, a **format tag on every revision** so that when metrics arrive the account's own data replaces folklore. Third, **guardrail checks in the review step**: exactly one question per post and no "comment X to get Y" patterns; a near-duplicate check across recent drafts and published posts (X bans duplicative content and decays repeat authors); excerpt caps and mandatory attribution for third-party sources; and platform-aware link handling — links stay in the post body on LinkedIn (no measured penalty, and link-in-first-comment is at least as safe), while on X the link belongs in the **first reply**, where it avoids both the weakest-format slot (2.25% median) and the 13× posting surcharge ($0.20 vs $0.015) ([Buffer](https://buffer.com/resources/data-best-content-format-social-media/), [X API pricing](https://docs.x.com/x-api/getting-started/pricing)). Don't A/B as two near-identical posts; rotate formats across weeks and let the `metrics` table compare them.

## Fireworks killed image generation, but deterministic cards were the better bet anyway

Fireworks removed image generation — its changelog entry for **June 10, 2026** reads "Audio inference and image generation are deprecated," with no migration path, and the docs index contains no text-to-image endpoint ([Fireworks changelog](https://docs.fireworks.ai/updates/changelog)). That rules out reusing the existing LLM provider; images must come from a second source, and there are three realistic families: deterministic rendered cards, harvested OG images, and paid generation APIs. The recommendation is **cards first, OG opt-in, paid generation last.**

Cards are a pure-Node build: **satori** (JSX→SVG; ~14.1k★, MPL-2.0; fonts must be supplied explicitly; a build-time `layout.wasm`) plus **sharp** for the SVG→PNG step gives a renderer with no headless browser ([vercel/satori](https://github.com/vercel/satori)); resvg-js is a working Rust/WASM alternative ([thx/resvg-js](https://github.com/thx/resvg-js)), and QuickChart renders Chart.js charts server-side (hosted API, or AGPL-3.0 self-host) for the occasional data visual ([QuickChart](https://quickchart.io/)). Templates worth shipping: a stat card, a quote card ("quote — author, source" plus a one-line take), a "what changed / why it matters" card, and a simple chart card; render at 1200×630 for feed previews and 1080×1350 or square for LinkedIn. This is cheap, deterministic, on-brand, and better aligned with trust evidence than AI art: a 5M-post dataset put LinkedIn image posts at ~14.4% engagement versus ~1.6% for X images, with documents/carousels near 37% (2025 data; treat magnitudes as directional) ([ZoomSphere](https://www.zoomsphere.com/data-reports/the-state-of-social-media-engagement-rate-in-2025)), while the Nature experiment above found AI-assisted content reduces perceived authenticity. Reuse the source's `og:image:alt` when present; otherwise generate alt text from the card's copy.

OG-image harvesting is the fallback and carries the pipeline's only real rights question. `og:image` is a required Open Graph property with optional width/height/alt fields ([ogp.me](https://ogp.me/)), and Node parsers are mature — `open-graph-scraper` and `metascraper` (which parses HTML you supply and never fetches) ([openGraphScraper](https://github.com/jshemas/openGraphScraper), [metascraper](https://github.com/microlinkhq/metascraper)). Normalize with sharp: X accepts ≤5 MB JPG/PNG/GIF/WEBP; LinkedIn's cap is **36,152,320 pixels** ([X media docs](https://docs.x.com/x-api/media/introduction), [LinkedIn Images API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/images-api)). No spec or library defines re-publication rights for a publisher's OG image, so the defensible policy is: rendered cards by default; OG images only as an explicit per-post choice with attribution and the source link in the post text — never the starred visual for a post whose value is the source's own artwork. Keep the untrusted-content stance here too: while researching, Diffbot's page footer contained hidden instructions aimed at reading agents — a reminder that URL-ingestion paths are an attack surface ([Diffbot](https://www.diffbot.com/products/extract/)).

Paid generation is a solved commodity if it is ever wanted. OpenAI's current image API (the gpt-image-2.5 family) is token-priced — **$8 per 1M image input tokens and $30 per 1M output tokens** — and requires organization verification ([OpenAI image guide](https://platform.openai.com/docs/guides/image-generation), [pricing](https://platform.openai.com/docs/pricing)). Black Forest Labs prices FLUX per megapixel (1 credit = $0.01): **FLUX.2 [pro] $0.03 for the first MP, FLUX.2 [klein 4B] ≈$0.014, FLUX.1 Kontext [pro] $0.04 / [max] $0.08** ([BFL pricing](https://bfl.ai/pricing)). Together AI and Replicate resell the same model family at similar or lower prices — **FLUX schnell ≈$0.003/image**, SDXL $0.0019/MP, flux-1.1-pro $0.04 ([Together AI](https://www.together.ai/pricing), [Replicate](https://replicate.com/pricing)). Cheap tiers are ample for decorative images; nothing here justifies premium tiers for a solo desk.

| Image option | Cost per post image | Rights / trust | Verdict |
| --- | --- | --- | --- |
| Rendered cards (satori + sharp) | ~$0 (compute only) | own design; trust-positive | **Default** |
| OG harvest (with sharp normalization) | ~$0 + resize | publisher-dependent; attribution + link required | Opt-in fallback |
| FLUX klein / schnell (BFL, Together, Replicate) | $0.003–$0.015 | synthetic; disclose | Decorative use, Phase 3 |
| FLUX pro / OpenAI gpt-image-2.5 | $0.03–$0.08; OpenAI token-priced | synthetic; disclose | Only if hero visuals ever matter |

Both upload flows are small extensions of what PostFlow already does. **On X:** upload with `POST /2/media/upload` (the simple upload suffices for cards; chunked initialize/append/finalize is for video), set alt text with `POST /2/media/metadata` (max 1,000 characters), and attach up to 4 photos by putting `media_ids` in `POST /2/tweets`; OAuth 2.0 user tokens with the `media.write` scope are sufficient ([upload](https://docs.x.com/x-api/media/upload-media), [metadata](https://docs.x.com/x-api/media/create-media-metadata), [create post](https://docs.x.com/x-api/posts/create-post)). Cost: the post request $0.015, media metadata $0.005, and the upload call billed under a $0.005 line item — roughly **$0.02 per image post** versus $0.015 without ([X pricing](https://docs.x.com/x-api/getting-started/pricing)). **On LinkedIn:** initialize with `POST https://api.linkedin.com/rest/images?action=initializeUpload` using `urn:li:person:{id}` as owner, PUT the binary to the returned URL, then create the post at `POST /rest/posts` referencing the image URN in `content.media.id` with `altText`; `w_member_social` plus a current `Linkedin-Version` header is the whole requirement ([LinkedIn Images API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/images-api), [Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api)). LinkedIn image posts are free via API. Keep `Linkedin-Version` in configuration because **202511 sunsets on November 16, 2026** ([LinkedIn versioning](https://learn.microsoft.com/en-us/linkedin/marketing/versioning)), and note that the MultiImage API reuses the same flow for several images — the foundation the carousel build rides on ([MultiImage API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/multiimage-post-api)). One system-design consequence: because approval belongs to a revision, the rendered artifact must be bound into the revision — hash the image bytes and store them alongside — so "approve the exact text" becomes "approve the exact post."

## Paste a URL or your own draft, atomize it, then write in your voice

The extraction ladder for a Node/TypeScript desk is: **(1) plain fetch plus `@mozilla/readability` with jsdom** — Apache-2.0, 11.5k★, returns title, textContent, byline, siteName, publishedTime, with a cheap `isProbablyReaderable()` pre-check and a DOMPurify sanitization recommendation for untrusted input ([mozilla/readability](https://github.com/mozilla/readability)); **(2) trafilatura as a Python sidecar** when extraction quality on the hard 10% matters more than stack purity — the benchmark-leading open-source extractor (7.0k★, Apache-2.0) ([trafilatura](https://github.com/adbar/trafilatura)); **(3) an external reader API** for JS-heavy or anti-bot pages — Jina Reader is the most capable (`r.jina.ai`; 20 RPM without a key; native PDF reading; cookie forwarding for content the user already has access to; explicitly no circumvention of access controls) but it is now Elastic-owned and its best reader models are non-commercially licensed, so treat it as convenience, not infrastructure ([Jina Reader](https://jina.ai/reader/)); self-hosted Firecrawl (AGPL-3.0, respects robots.txt by default, parses web-hosted PDF/DOCX) is the license-clean alternative ([Firecrawl](https://github.com/firecrawl/firecrawl)). For pasted own-content, accept text and markdown directly, and PDF/DOCX via the same parser path. Readwise Reader is worth copying as a pattern rather than adopting as a dependency: it ingests URLs or clean HTML and exposes highlights as first-class objects with webhooks ([Readwise Reader API](https://readwise.io/reader_api)).

The repurposing pattern with the strongest open-source precedent is **atomize → adapt**, and its clearest implementation is AgriciDaniel/claude-repurpose (MIT, ~160★): extract the source, mine **5–15 reusable atoms — stats, quotes, insights, questions, contrarian takes** — then generate in parallel an 8–12-tweet thread, a LinkedIn post plus 10–12-slide carousel script, standalone tweets, a poll, five quote-graphic candidates and a 7-day calendar, governed by platform spec files and a `--voice` override ([claude-repurpose](https://github.com/AgriciDaniel/claude-repurpose)). The architectural lesson — deterministic atom extraction first, generative per-platform adaptation second — maps directly onto PostFlow's immutable revisions: atoms become a source-linked table, drafts reference the atoms they used, and the existing angle-first prompts consume atoms instead of raw article text. Single-format precedents exist (TwitterThreadCreator's newspaper3k→Gemini→n8n pipeline with structured JSON output and per-part delays ([repo](https://github.com/SohamXYZDev/TwitterThreadCreator))), and the commercial consensus is "AI drafts, human approves" with agent surfaces (Typefully's MCP and API ([llms.txt](https://typefully.com/llms.txt)), Postiz's MCP/CLI). The concrete flow for PostFlow: paste URL or text → extract → review atoms with their source quotes → toggle or edit atoms → generate LinkedIn and X drafts from selected atoms through the existing drafting pipeline. The same flow serves the owner's own writing unchanged, except that attribution and excerpt caps are relaxed for self-authored input.

Voice preservation has one dominant product pattern — **generate from the user's own past posts** (Hypefury: "our AI learns from your posts and generate posts that sound like you") — plus prompt-level voice-rules files (claude-repurpose ships "voice rules" reference files and honors `--voice witty`) ([Hypefury](https://hypefury.com/), [claude-repurpose](https://github.com/AgriciDaniel/claude-repurpose)). There is no widely adopted open-source voice-profile standard, and fine-tuning is a dead end at this data volume (a TinyLLaMA-LoRA LinkedIn generator exists, but it is a demo, not a method) ([repo](https://github.com/brezzergit/LinkedIn-LLM-Post-Generator)). PostFlow already stores its owner's approved revisions — the strongest possible corpus. The build is therefore retrieval, not training: keep 5–10 topic-matched approved posts as few-shot style exemplars in the drafting prompt, plus a Settings-visible "voice rules" note the owner can edit (banned words, sentence length taste, emoji policy — martinopedal's em-dash-and-emoji bans are a useful starting template ([repo](https://github.com/martinopedal/linkedin-auto-poster))). Add one opinion-extraction primitive: let the user highlight a passage in the intake box, and turn highlighted text into a "quote + your take" draft where the quote is verbatim and attributed — the Readwise model, and the highest-signal way to surface what the owner actually thinks.

Legally, the line is not attribution. US fair use is a four-factor, fact-specific test, and "merely crediting a creator" does not convert an infringing use into fair use; in *Harper & Row v. Nation Enterprises*, roughly 300 words weighed against fair use because they were the heart of the work ([Copyright Alliance](https://copyrightalliance.org/5-fair-use-myths-social-media/)). The safe operating pattern for found articles: **one short quote maximum (never the heart), the owner's commentary as the substance of the post (a transformative purpose), automatic "— author, publication" attribution plus the source link, and no full-text reproduction** ([SnipPost](https://snippost.io/blog/quote-articles-social-media.html)). Paywalls and anti-bot gates are a hard boundary — publicly visible previews or the user's own authenticated access only, matching the published stances of Jina and Firecrawl. Own content has no third-party copyright problem at all, which argues for making it the first-class intake path even though the marketing story is "repurpose what you find." This is design guidance, not legal advice; no case law was found on machine-generated social excerpts specifically.

## The compliance envelope is narrower than the feature temptation — and the approval gate is load-bearing

X's rules are unusually explicit and, read carefully, friendly to exactly what PostFlow is. The Automation Rules bless auto-broadcasting helpful information and automated posts based on outside sources such as RSS "if you are authorized to publish the info," while banning in the same document: non-API automation such as scripting the X website (potential permanent suspension), automated likes, keyword-triggered automated replies, bulk follows, unsolicited DMs, duplicative near-identical posts, trending-topic automation, and AI-powered reply bots without prior written approval from X ([Automation Rules](https://help.x.com/en/rules-and-policies/x-automation)). The Developer Policy adds the consent requirement that makes PostFlow's architecture mandatory rather than optional: a service must **"show exactly what will be published"** before publishing, and authentication alone is not consent ([Developer Policy](https://developer.x.com/en/developer-terms/policy)). The revision-bound approval gate is precisely that showing — and it should be described that way in the UI and docs, not left as an implicit guarantee.

LinkedIn's User Agreement bans bots or unauthorized automated methods "to create, comment on, like, share, or re-share posts, or otherwise drive inauthentic engagement," and its help pages ban third-party software that automates activity, with documented enforcement including false positives on manual behavior ([User Agreement](https://www.linkedin.com/legal/user-agreement), [Automated activity help](https://www.linkedin.com/help/linkedin/answer/a1340567)). Against that, LinkedIn's own developer catalog markets **Share on LinkedIn** — member-authorized posting with `w_member_social`, which is what PostFlow uses ([Share on LinkedIn](https://learn.microsoft.com/en-us/linkedin/consumer/integrations/self-serve/share-on-linkedin)). The contradiction is API Terms §3.1(26), under which developers agree not to "[u]se the Content or the APIs to automate posting on the LinkedIn Services"; the plausible reading (it targets bots acting without member action, not member-authorized publishing through LinkedIn's sanctioned products) is unconfirmed, and this is the single largest unresolved risk in the plan — worth a lawyer's hour before the account is connected ([LinkedIn API Terms](https://www.linkedin.com/legal/l/api-terms-of-use)). Practical limits: **150 share requests/day per member** and 100,000/app/day ([Share docs](https://learn.microsoft.com/en-us/linkedin/consumer/integrations/self-serve/share-on-linkedin)); analytics for personal posts are gated behind the reviewed Community Management API, so LinkedIn metrics are manual or partner-gated for a solo desk ([Increasing Access](https://learn.microsoft.com/en-us/linkedin/marketing/getting-access)); and self-serve eligibility excludes businesses that rely on the APIs as a fundamental aspect of their business — the desk comfortably fits as a personal tool ([API Terms §1.4](https://www.linkedin.com/legal/l/api-terms-of-use)).

Costs in October 2026: X is pay-per-usage — **$0.015 per text post, $0.20 per post containing a URL, $0.005 per media-metadata request, $0.001 per owned read, $0.005–$0.01 for counts and metrics; reads are deduplicated within 24 hours and capped at 3M posts/month**, with $20 in free credits available to new payers ([X API pricing](https://docs.x.com/x-api/getting-started/pricing)). A solo desk posting ~20 text posts a month with occasional media lands around **$0.30–$1/month**; link posts are the only plausible budget breaker (40 links ≈ $8/month), which is one more reason the link-in-reply option belongs in Phase 1. LinkedIn's APIs are currently free, with LinkedIn reserving the right to charge ([API Terms §8.2](https://www.linkedin.com/legal/l/api-terms-of-use)). Image generation at card scale is pocket change (~$0–$0.03/post), so the dominant marginal cost remains Fireworks LLM usage — and the features proposed here add at most one extra LLM call per draft, reusing cached article analysis.

Enforcement reality, in descending probability for a desk like this: browser automation first (never), automated liking/commenting/replying second, duplicate content third, volume-based flags fourth, with AI-slop flooding as an emerging demotion and reporting target — LinkedIn's July 2026 slop-report button and the ~25% AI-generated prevalence estimate explain why "obviously AI" content carries reputational risk even where no explicit ranking penalty is documented ([TechCrunch](https://techcrunch.com/2026/07/30/linkedin-adds-a-button-to-report-ai-generated-slop/), [The Register](https://www.theregister.com/ai-and-ml/2026/07/09/ai-slop-writing-has-taken-over-the-internet-particularly-linkedin-and-x/5269525)). Compliance measures the system must keep and extend: API-only publishing (already); human approval bound to an immutable revision (already — strengthen by hashing any attached image into the revision); **no automated engagement actions of any kind, ever**; human-scale cadence with per-platform caps well under limits (already); per-account rate-limit tracking and a publish audit log (BrightBean's pattern, worth adding to the existing attempts history); LinkedIn token operations — the ~60-day member token with an expiry reminder at 14 days (martinopedal's pattern, ([repo](https://github.com/martinopedal/linkedin-auto-poster))); a kill switch per platform (already, as pause switches); and a near-duplicate check so that platform-independent drafts produce genuinely tailored text rather than identical cross-posts, which X's rules explicitly prohibit.

## Build order: cards and intake first, carousels and voice second, the loop last

Everything below is sequenced by (a) answering one of the three stated wants, (b) leveraging what already exists, and (c) keeping the compliance surface flat. Effort assumes one developer: **S ≈ 1–2 days, M ≈ 3–5 days, L ≈ 1–2 weeks**. Phase 0 is mechanical: finish the account-connection work in `SETUP.md` (X app with write scopes, LinkedIn Share product), because no publishing feature can be validated without a live path — and verify X's current pay-per-use pricing before wiring anything, as the README itself warns.

| Phase | Feature to build | Rationale (evidence) | Effort |
| --- | --- | --- | --- |
| 1 | **URL / paste intake + atomization** — accept a URL or pasted text, extract with Readability (+ trafilatura sidecar optionally), mine typed atoms with source offsets, feed existing angle-first prompts | Own content has zero legal friction; the claude-repurpose pattern is the proven intake architecture; atoms make every later format cheap; answers want #3 directly | M (3–5 d) |
| 1 | **Stat/quote card renderer + image upload to X and LinkedIn** — satori+sharp templates, 1200×630 and 1080×1350, alt text, per-platform image toggle | Fireworks image gen is gone; LinkedIn images are the strongest visual evidence; prerequisite for carousels; ~$0.02/post on X, $0 on LinkedIn | M (4–6 d) |
| 1 | **Engagement format pack** — new rewrite presets (Thread draft, Carousel script, Add a genuine question, What-if thought experiment, Contrarian take, 3 takeaways, Quote + take) plus a format tag on revisions | Prompt-only cost; encodes the evidence-backed structures and the "what-if" wrapper as a testable hypothesis rather than building pipelines per format | S (1–2 d) |
| 1 | **X link-in-reply option + cost guard** — optionally split an external link into a first reply, priced as a separate post | Link posts are the weakest format (2.25% median) and cost 13× more ($0.20 vs $0.015); the reply preserves context at the cheap rate | S (1 d) |
| 2 | **LinkedIn document/carousel pipeline** — 6–10 slides generated from selected atoms by the card renderer, published as a document or multi-image post | Carousels are the only format ranked #1 by both independent 2026 studies; completes the image investment | L (1–2 wk) |
| 2 | **Voice profile from approved posts** — 5–10 topic-matched approved revisions as few-shot exemplars + an editable voice-rules note | Learned-voice is the top paid-tool promise and the corpus already exists; no fine-tuning, no drift risk | M (3–5 d) |
| 2 | **X threads with delays** — multi-part drafts, one approval for the thread, per-part costs recorded, reply-chain publish with reconciliation | Thread drafting is in the format pack; the publishing layer is what threads add; text-first is X's best-evidenced lane | M (3–5 d) |
| 2 | **Quality validator** — banned slop phrases, excerpt caps, mandatory attribution, one-question rule, near-duplicate detection, surfaced as review warnings | Protects trust and compliance; martinopedal's 50+ phrase list is a ready template; cheap insurance against LinkedIn's repetitive-content spam rules | S/M (2–3 d) |
| 2 | **OG image opt-in fallback** — fetch and normalize OG images when the owner explicitly chooses one, with attribution and source link | Covers pages cards suit poorly; keeps the rights question explicit and per-post | S (1–2 d) |
| 3 | **Metrics read-back + format scorecard** — X owned reads ($0.001/resource) into the `metrics` table; LinkedIn manual entry or a Community Management API application decision; join performance to format tags | Turns format guesses into the account's own data; X side is nearly free; enables evergreen recycling of top performers | M/L (1 wk+) |
| 3 | **Approval-feedback ranking** — explicit ratings plus implicit signals (skips, rewrites chosen) with time decay | condenseit's model, proven and simple; improves briefing quality over time | M (3–5 d) |
| 3 | **Paid image generation (optional, decorative)** — one provider, cheap tier, disclosure when synthetic | Available if wanted, but cards outsell AI art on trust; not needed for core value | S integration; defer |
| 3 | **MCP/agent surface for drafts** — let an assistant create drafts for approval | Ecosystem convention (Postiz, Typefully, TryPost); only worth it after the flows stabilize | M; defer |

**Do not build, at any phase:** browser automation (Puppeteer, extensions, session-cookie scripting) against either platform — X ties it to permanent suspension and LinkedIn restricts accounts for it, regardless of how many stars the pattern has on GitHub; automated likes, comments, replies, follows or DMs; engagement pods or any reciprocal-engagement feature; "Plugs"-style auto-comment or auto-repost loops (LinkedIn explicitly bans repetitive automated comments); keyword-triggered reply bots (X requires prior written approval and bans keyword-only triggers); fake or composite personal stories (false/misleading content rules); trending-topic automation; engagement-bait phrasing and artificial polls; paywall or anti-bot circumvention; and fine-tuning a voice model (wrong tool for this data volume).

None of these questions block Phase 1.

## Conclusion

The survey's most useful surprise is an inversion: PostFlow's unglamorous machinery — revision-bound approvals, ambiguity reconciliation, dedupe, explainable scoring — is what the ecosystem mostly lacks, while the popular repos are strong precisely where PostFlow has gaps: intake breadth, visual artifacts, and format variety. That makes the roadmap a copying exercise, not an invention one, and it lowers the risk of every phase: each roadmap feature already has a working implementation somewhere to consult. The second surprise is that the sustainable-versus-manipulative question has a technical answer that matches the ethical one — X's own ranker pays 10× for predicted replies over likes and added +15 specifically for mutual-follow conversations, LinkedIn demotes engagement mechanics and rewards timely commentary with expertise, and both platforms are tightening around manufactured engagement, pods, copypasta and AI slop. The formats that win with real audiences are the formats that would exist without the metrics.

What this changes for the build: on LinkedIn the image pipeline *is* the engagement feature, not decoration — carousels are the only format two independent datasets rank first — while on X the text carries the load and images are garnish; the intake feature is the multiplier that feeds both, because atoms make carousel slides, threads, quote cards and "what-if" analyses nearly free to produce; and the one thing to resolve before writing more code is not technical. Decide the posture on LinkedIn's automate-posting clause first; every phase below assumes that member-authorized, human-approved, API-based publishing is a stance the owner is willing to hold.

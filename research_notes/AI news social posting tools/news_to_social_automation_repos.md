# Open-source projects and tools that turn AI/tech news into social media posts (X/LinkedIn)

Research date: 2026-10-15. Star counts and "last push" values were read live from the GitHub API (via authenticated `gh`) on this date. Primary sources are repo READMEs, docs, and platform APIs (n8n templates API, HN Algolia API). General web search was unavailable in this session; GitHub search, direct README/doc fetches, n8n's template API and HN's Algolia API were used instead. Where a fact could not be verified from a primary source it is flagged in Gaps.

Context this research serves: PostFlow is a Node/TypeScript self-hosted desk — RSS + GitHub sources → LLM analysis → briefings → auto-drafted LinkedIn/X posts with approval-gated scheduling (repo README: `/Users/suyogadhikari/Documents/work/personal/suyog007/PostFlow/README.md`).

## Which GitHub repos aggregate news/RSS and auto-generate social posts?

### Takeaway
There is no dominant, high-star, dedicated "news → social post" bot. The space splits into four clusters: (1) small indie scripted pipelines (13–533★) that are the closest functional analogs to PostFlow; (2) large self-hosted schedulers (Postiz 37.2k★, Mixpost 3.8k★, BrightBean 2.5k★, TryPost 707★) that added RSS-intake + AI drafting as features; (3) digest-only aggregators with excellent ranking machinery but no social publishing (CondenseIt 89★); (4) bot-automation ecosystems (n8n templates) that cover the workflow with much weaker dedupe/approval rigor. The single most PostFlow-like system found is `martinopedal/linkedin-auto-poster` (13★): RSS/Releases intake → keyword scoring → research agent → dual-model draft/critique → validator → GitHub-PR approval → LinkedIn publish.

- **martinopedal/linkedin-auto-poster** — 13★, Python, pushed 2026-06-29, MIT. README: "Fetches RSS feeds, scores relevance, researches claims, drafts in your voice, and publishes through a GitHub PR approval workflow." Architecture: 06:00 UTC GitHub Actions cron → fetch RSS + GitHub Releases → score → research agent (article fetch, Microsoft Learn search, Terraform verify; tools enabled) → Claude Opus draft → GPT-5.4 critic → sanitize/validate → one GitHub PR per draft → human adds `approve-post` label and merges → `publish-approved.yml` posts via LinkedIn API. Scoring is deterministic: exclude-keyword hard drop; include-keyword hits (title+summary+categories) + update-type weight (GA=3, public preview=2, retirement/deprecated=2, private preview=1, blog/notice=1) + category keywords double-counted; standalone threshold 12; below-threshold items go to a weekly roundup; high-relevance previews promoted (max 2/run); `max_posts_per_run: 5`; dedupe by normalized URL + title hash against `data/seen.json`; 7-day age cutoff; `publish.max_age_days: 7` skips stale drafts; drafts unapproved for 7 days auto-close. Failure handling: fetcher retry + normalization; on publish failure creates a GitHub issue; file guard blocks publish unless only `drafts/*.md` changed; branch protection. Safety: validator catches 50+ AI-sounding phrases, emoji/em-dashes, PII, blocked company names, unapproved URL domains; SSRF protection (private IP blocking) on research tools; prompt-injection protection with XML-style delimiters. Token ops: LinkedIn tokens ~60 days; `token-reminder.yml` opens an issue when within 14 days of expiry. Also has a content calendar for non-news opinion posts (voice profile with writing patterns). ### Inferences
- The market gap PostFlow occupies (news → ranked briefing → dual-platform drafts → approval-gated scheduling, self-hosted) is real: the only GitHub project with near-identical scope has 13★, and the big schedulers treat news intake as a secondary "RSS auto-post" plug-in rather than the core workflow.
- Indie projects converge on GitHub Actions + scripts + file-based state; self-hosted schedulers converge on always-on services (Postiz uses Temporal). PostFlow's worker+Postgres "modular monolith" sits between the two and is more robust than the former for scheduling precision.
- Digest projects (condenseit, giftedunicorn, Jimmuji) attract more stars than news→social posters, suggesting the audience values curation quality first; posting is an add-on.

### Gaps
- No famous/high-star (>1k★) open-source project dedicated to "AI/tech news → auto-generated X/LinkedIn posts" was found; if one exists, it did not surface in GitHub search terms used ("ai news bot", "rss twitter bot", "linkedin ai post", "news to twitter", "ai twitter bot llm", "hacker news twitter bot", "ai news digest", "twitter thread bot", "ai social media automation", "linkedin content generator").
- `transitive-bullshit/twitter-agent` was checked and does not exist; no evidence for any similarly named large "AI twitter agent" repo.
- Reddit/Mastodon-only bots (e.g., bsky-bot landscape) were out of scope and not searched.

## How do automation-platform ecosystems (n8n/Make/Zapier/IFTTT) handle "AI news → LinkedIn/X post"?

### Takeaway
n8n is the de-facto center of this workflow: hundreds of community templates cover news/RSS → LLM → social post. The most-viewed templates (#4005: 27.9k views; #4968: 20.6k views) show the popular pattern is a Google-Sheet queue + LLM + an explicit human approval step (email) + posting node, and image generation (DALL-E) is a common engagement feature. Zapier's native Twitter integration was deprecated in 2023 due to X API pricing — a structural warning for anything built on X APIs. Make hosts a Postiz app integration but its template gallery could not be scraped for verification.

### Cited Findings

### Inferences
- The n8n pattern "Sheets as queue + LLM + email/Slack/LINE approval + platform node" is the community's standard human-in-the-loop; it approximates PostFlow's approval gate but without content hashing, revision binding, or reconciliation. Its attraction is speed of setup; its weakness is no dedupe/ranking beyond the LLM prompt.
- High view counts on approval-oriented and image-generating templates are directional evidence that users want (a) a checkpoint before publishing and (b) visuals, matching Postiz's shipped "AI images" feature.
- Zapier's Twitter deprecation shows that X-API-dependent pipelines need a self-hosted/own-app-credential path (as PostFlow does); n8n templates advertising "free Twitter API" are built on X's free write-only tier, which limits reading/reconciliation.

### Gaps
- Make.com template contents and IFTTT's current Twitter/RSS support could not be verified (JS-rendered pages; web search unavailable). No claim made for IFTTT.
- Zapier's current RSS→X path: the deprecation page is from 2023; whether a replacement Twitter integration exists as of Oct 2026 was not verified.

## What do general social-media tools with AI features provide around news intake → drafting → scheduling → engagement, and how is it implemented?

### Takeaway
Postiz is the reference implementation for this whole pipeline in open source: 37.2k★, AGPL-3.0, and it ships RSS auto-posting with optional AI rewriting, AI posts/images/videos, approvals, Plugs (auto-repost/auto-comment on high-performing posts), analytics, MCP/CLI/public API, and a Temporal-based always-on scheduler. Mixpost (3.8k★) is the mature PHP/Laravel alternative with engagement-oriented "post versions & conditions" but a commercial Pro tier and no AI mentioned in its Lite README. BrightBean (2.5k★) and TryPost (707★) are the newest credible entrants; TryPost explicitly targets AI-agent-driven posting.

### Cited Findings
- **Postiz** (https://github.com/gitroomhq/postiz-app): README tagline "The ultimate agentic social media scheduling tool"; tech stack: pnpm monorepo, NextJS, NestJS, Prisma (PostgreSQL default), **Temporal** (workflow engine — they published a "Migration to Temporal" guide: https://docs.postiz.com/self-host/installation/migration), Resend for email. License AGPL-3.0. Cloud vs OSS split documented: OSS is fully featured (no feature gating — "We do not gate features or limit the license"); you bring your own platform developer apps and AI provider keys.
  - **News intake**: "RSS auto-posting — Turn a feed into scheduled posts, with or without AI rewriting" (https://docs.postiz.com/general/automations/auto-post-rss). Mechanics from the docs: add feed URL (validated on entry), choose whether the newest existing item posts immediately or wait for the next new one, choose "Post on the next available slot" (uses channel time slots, keeps automation inside posting rhythm) or "Post immediately" (advised only for time-sensitive feeds), toggle "autogenerate content" (AI writes per-platform posts) or supply your own template, toggle "Generate picture" (AI image per post), pick channels, activate toggle. Docs advice: start with one channel/feed; use next-available-slot so bursts spread instead of 5 posts at once; high-volume feeds exhaust slots, filter at source; autogenerated posts consume AI credits.
  - **AI features**: AI Copilot / AI generation of whole posts, images, and videos (cloud: metered quotas with Postiz-managed keys; OSS: bring your own OpenAI etc. keys, no quota); "Smart Agent"; video clipping (turn a long YouTube video into captioned vertical clips; API creates draft posts per clip, "Nothing is scheduled or published": https://docs.postiz.com/public-api/clipping/create). In-app design editor via Polotno (self-host config: https://docs.postiz.com/self-host/configuration/polotno).
  - **Engagement-oriented output**: threads and comments — "Multi-part posts, what each platform does with them, and delays between parts" (https://docs.postiz.com/general/composer/threads-and-comments); **Plugs** — "Auto-repost and auto-comment when a post performs well" (https://docs.postiz.com/general/automations/plugs); per-channel time slots; analytics for platforms that report metrics (https://docs.postiz.com/general/analytics).

### Inferences

## Which include engagement-oriented output or images, and how?

### Takeaway
Engagement features cluster into: AI images (Postiz "Generate picture", n8n DALL-E/image nodes, LinkedIn carousels), threads with inter-post delays (Postiz; social-push supports long-form on multiple platforms), auto-boost loops on high-performing posts (Postiz Plugs; Mixpost conditions), best-time/slot scheduling (Postiz time slots, Mixpost queues, BrightBean queues), and channel-specific formatting (TryPost per-network adaptation, crawl posts for LinkedIn documents). - n8n: #4968 uses DALL-E for images; #2933 generates an image per RSS item (nodes include HTML + X + AI Agent); #17311 creates "AI news shorts" (video) from Hacker News via Blotato; #9470 (search result) "Generate MemeCoin Art with Gemini Flash & NanoBanana and Post to Twitter". URLs: https://n8n.io/workflows/4968/, https://n8n.io/workflows/2933/, https://n8n.io/workflows/17311/
- Carousels/documents: AgriciDaniel/linkedin-content-creator generates "text posts, image posts, and carousel/document posts" (https://github.com/AgriciDaniel/linkedin-content-creator); TheAdmanCross pipeline generates a carousel → PDF → native LinkedIn document post via Buffer (https://github.com/TheAdmanCross/claude-linkedin-auto-poster).
- Mixpost: post versions per network + "automate follow-up comments on high-performing posts"; media library integrates stock image sources (https://github.com/inovector/mixpost).
- BrightBean: unified inbox with sentiment analysis and threaded replies (engagement inbound), queues auto-assigning to best slots (https://github.com/brightbeanxyz/brightbean-studio).
- Closed: Taplio (write in your voice, schedule at best time), Postwise ("viral posts"), Buffer AI Assistant (generate/repurpose/optimize) — taglines only, see Q3.
- martinopedal's validator bans emoji and em/en dashes ("Formatting rules - No emoji, no em dashes, hashtag limits, character counts") — an anti-hype, engagement-cautious stance worth noting as a contrast to "viral" tools (https://github.com/martinopedal/linkedin-auto-poster).

### Inferences
- In open source, images are the single most common engagement feature and are implemented as "generate picture" toggles on the LLM post step, not as design/carousel systems (carousels remain an indie script or closed-tool niche).
- The engagement loop (observe performance → auto-boost) exists only in the two mature schedulers (Postiz, Mixpost), and only as generic post-level automation; nobody open-source closes the loop from engagement metrics back into news ranking (an opening for PostFlow's `metrics` table if it starts collecting them).
- Polls/question-posts and hook-generation were not found as implemented features in any open-source system reviewed; they exist only as prompt/voice-guide concerns (martinopedal's voice profile "CTA patterns", "topic pillars").

### Gaps
- No verified open-source implementation of generated polls/questions as output; no evidence found either way for X poll API usage in these projects.
- Closed tools' actual hook/carousel algorithms (Taplio, Postwise, Hypefury, Ocoya) are undisclosed; no independent quality evidence was gathered.

## What architectural lessons stand out (ranking/dedupe, approval gates, retries, account safety)?

### Takeaway
The strongest systems share six patterns: (1) deterministic, explainable scoring on top of LLM analysis (martinopedal's additive keyword/type formula; condenseit's multi-signal additive profile; PostFlow's own model-scores-then-code-scores); (2) multi-layer dedupe with persisted seen-state (URL + title hash + age window; ID dedupe; content-hash-cached embeddings); (3) human approval as a first-class, enforced gate (PR + label + file guard; email/Slack/LINE; approval-link; draft-only browser flows); (4) explicit ambiguity handling instead of blind retry (Postiz "missing releaseId" reconcile endpoints; PostFlow-style "unconfirmed" states — martinopedal instead opens an issue on failure); (5) cost/cadence engineering (hourly collect + daily publish = same AI cost, 24× coverage; per-run caps; budgets with alert/stop thresholds; next-available-slot spreading); (6) account safety via official APIs + token-expiry ops, with browser-session automation and cookie scraping as a documented-but-riskier alternative.

### Cited Findings
- **Ranking**: martinopedal scores items deterministically (exclude keywords hard-drop; include hits in title+summary+categories; RSS-category hits double-weighted; update-type weight GA=3/preview=2/retirement=2/private preview=1/blog=1; threshold 12 for standalone vs weekly roundup; max 2 promoted previews; max 5 posts/run) — https://github.com/martinopedal/linkedin-auto-poster. CondenseIt's ranking is additive across signals: keywords, term overlap, bigram phrases, TF-IDF cosine, category, source, three implicit channels, synonym boost, semantic embedding similarity, LLM-extracted topic score, and optional LLM rerank (top-K=30 blended at weight 0.3), with every card showing a "Why ranked here?" breakdown — https://github.com/wildlifechorus/condenseit.
- **Preference learning** (CondenseIt): explicit star ratings 1–5 (4–5 boost, 1–2 penalize), implicit signals — read ≈ mild positive (~3.8 stars), save-for-later ≈ strong positive (~4.5), dismiss ≈ mild negative (~1.5), implicit weight scaled 0.5; exponential time decay (default half-life 30 days); learning activates at ≥5 ratings; cold-start via plain-text interest description that the LLM turns into keywords/synonyms/profile. Embeddings cached in SQLite keyed by URL+content hash — https://github.com/wildlifechorus/condenseit.
- **Dedupe**: URL-normalization + title-hash against `data/seen.json` with 7-day dedupe window and file-locked state store (martinopedal); SQLite dedupe by source item ID (solopilot); embedding cache keyed by URL + content hash (condenseit).
- **Approval gates**: GitHub PR per draft with `approve-post` label + merge to trigger publish, file guard limiting changes to `drafts/*.md`, drafts auto-closed after 7 days, preview rendered in the PR body for phone review (martinopedal); preview link + comments (Postiz); configurable stages none/optional/internal/internal+client with threaded comments + audit trail (BrightBean); one-click approve/reject with "same rules, same limits, same approvals" for agents (TryPost); email approval (n8n #4005), Slack approval (#9710), LINE approvals with stateful resume via Google Sheets bridge (#12866); draft-only + final user confirm in browser (social-push).
- **Retries and failure handling**: generator retries up to 3× and notifier failures degrade gracefully (giftedunicorn); fetcher retry + normalization (martinopedal); publish failure → GitHub issue alert; token-expiry issue at 14 days before the ~60-day LinkedIn token expiry (martinopedal); automatic retries + per-account rate-limit tracking + 90-day audit log (BrightBean); Postiz `releaseId "missing"` reconciliation endpoints (https://docs.postiz.com/public-api/posts/missing-content); budget circuits — CondenseIt stops the pipeline before OpenRouter daily/monthly budget limits are exceeded (https://github.com/wildlifechorus/condenseit); solopilot $200/month budget, alert at 80%, stop non-essential workflows at 100%, `DRY_RUN` (https://github.com/Wifsimster/solopilot).
- **Cadence/cost**: solopilot's ADR-0001 "hourly collect, daily publish" gives "24× more coverage than a single run, for the same AI cost" (https://github.com/Wifsimster/solopilot); Postiz advises next-available-slot so a burst of feed items spreads out instead of publishing five things at once (https://docs.postiz.com/general/automations/auto-post-rss); n8n templates without per-run caps or dedupe are the counterexample (#3822 posts whatever the LLM returns each schedule).
- **Account safety / platform risk**: Postiz README compliance section: official platform-approved OAuth flows; "Postiz does not automate or scrape content from social media platforms"; users authenticate directly with platforms, tokens not proxied (https://github.com/gitroomhq/postiz-app). BrightBean: "direct first-party API integrations... no aggregator middleman" (https://github.com/brightbeanxyz/brightbean-studio). Zapier deprecated its Twitter integration on 2023-08-31 due to Twitter API policy/pricing (https://zapier.com/apps/rss/integrations/twitter) — X pricing/API policy is a standing platform risk. Counterexample approaches: solopilot scrapes X via session cookies (`auth_token`, `ct0`) and auto-detects GraphQL IDs (https://github.com/Wifsimster/solopilot); social-push automates browsers using the user's own logged-in browser with saved state files (https://github.com/jihe520/social-push); zackfounder runs LinkedIn/X/Bluesky "through a browser you" control (https://github.com/zackfounder/social-media-automation-agent). Buffer is still used as the scheduling/publishing backend by the carousel pipeline (TheAdmanCross) — evidence that even indie builders offload posting to existing schedulers.
- **Content safety**: banned-phrase list (50+ AI-sounding patterns), emoji/em-dash bans, PII and blocked-company-name checks, approved-domain URL whitelist, SSRF private-IP blocking on research tools, and prompt-injection protection with XML delimiters (martinopedal) — the most rigorous content-safety stack found; CondenseIt exposes score transparency ("Why ranked here?") and admin-adjustable weights.

### Inferences
- Ranking quality in the wild is dominated by two designs: hand-tuned additive keyword weights (martinopedal; also what PostFlow does pre-LLM) and learned preference profiles (condenseit). Both keep the final ordering in deterministic code and use the LLM only for per-item features — the same separation PostFlow implements. LLM-only ranking (n8n #3822, #4968) trades explainability for setup speed.
- Approval architecture is the clearest differentiator between "toy" and "trustworthy" systems. PR-based approval (martinopedal) is the strongest enforcement found next to PostFlow's revision-bound approvals; email/Slack/LINE approvals don't bind an approval to immutable content, so they can approve mutable drafts.
- For account safety, the field is unanimous in preferring official OAuth APIs for anything resembling production, and explicit about scraping as the risky fallback; token expiry planning (60-day LinkedIn tokens, reminders) is a recurring operational task that PostFlow should keep automated.
- The weakest coverage across almost all systems is reconciliation after ambiguous publish results; only Postiz ships explicit reconcile endpoints, and PostFlow's "unconfirmed" state + timeline read-back on X goes further than anything found.

### Gaps
- No public post-mortem/suspension reports from the scraping-based projects (solopilot, social-push, zackfounder) were found, so their account-safety risk is inferred, not measured.
- HN searches ("twitter bot", "LLM tweets", "GPT twitter bot", "Show HN social media bot", "rss auto post", "AI news") surfaced mostly old/low-engagement threads: the best context signals were "Ask HN: Can we please limit the AI news flood?" (868 pts, 403 comments, https://news.ycombinator.com/item?id=49657850) and "Emergent Mind: AI News, Curated and Explained by AI" (121 pts, https://news.ycombinator.com/item?id=35356928). No HN thread with deep architecture discussion of a news→social bot was found.
- Product Hunt and indie-hacker blog posts were not consulted (no web search available); closed-tool feature notes are tagline-level only.
